# Write a user persona

Use this skill after `write-user-profile` when a profile needs a memorable fictional representative for discussion. Update `1-user-profiles-personas.md` under the linked profile. Do not create an unlinked persona or present it as a real user.

## Method

1. Read the referenced profile, all source evidence and the linked project intake before drafting.
2. Give the persona a stable ID and fictional name, then link it to exactly one primary profile.
3. Summarise the role in the task, primary goal, trigger, current behaviour, workaround, context, knowledge, confidence, barriers, support needs and what success means.
4. Mark each attribute as reported, observed, provisional, conflicting or unknown where that distinction matters. Use no unsupported demographic detail, quotation, motivation or accessibility claim.
5. Keep the persona focused on decisions the project must make. Do not turn it into a biography or a permission model.
6. Add a validation plan: who will check it, against which real task or evidence and by when.
7. Link the persona to stories only after those stories exist. If the evidence changes the profile or goal, return to the affected profile before editing the persona.

## Quality gate

The persona remains `Provisional` until its important attributes have been checked with representative users or direct evidence. A polished persona is not evidence by itself. A persona must not be used to justify a requirement whose user value or acceptance remains unknown.
